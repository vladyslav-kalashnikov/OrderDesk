# OrderDesk

Десктопна програма (PySide6 + Playwright): акаунти з проксі моніторять наявність товарів
і за потреби додають їх у кошик. Сесії зберігаються, тож вхід — один раз.

## Встановлення (один раз)

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/python -m playwright install chromium
```

## Запуск

```bash
./venv/bin/python -m devsite          # демо-магазин на :8765 (окрема вкладка терміналу)
./venv/bin/python -m dashboard        # програма; --demo додасть демо-замовлення
```

Демо-акаунт для devsite: `demo@example.com` / `demo12345`.
Худі завжди в наявності, кросівки з'являються через 30 с, годинник — лише після
відкриття `http://127.0.0.1:8765/admin/restock/watch`.

## Як користуватись

1. **Проксі** → «+ Проксі»: по рядку `http://user:pass@host:port`, `socks5://…`, `host:port:user:pass`.
   «Перевірити» покаже IP і затримку.
2. **Акаунти** → «+ Акаунт»: email, пароль (іде в Keychain), проксі.
   «Увійти» — автоматично; «Увійти вручну» — відкриє браузер для капчі/2FA.
3. **Моніторинг** → «+ Завдання»: акаунт, посилання на товари (по рядку), режим, інтервал.
   «▶ Старт» / «■ Стоп» — для виділених або для всіх.
4. **Кабінет**: «Бажане» — товари на моніторингу, «Кошик» — що додав рушій.
5. **Кабінет → «↻ Оновити замовлення»**: програма заходить у «Мої замовлення» кожного акаунта
   і збирає номер, дату, суму, статус і ТТН. Нові замовлення додаються, у наявних оновлюються
   статус і ТТН, а кожна зміна статусу йде в історію (таймлайн у панелі деталей).
   Автооновлення за розкладом — «Налаштування» → «Автооновлення замовлень, хв».
6. **Налаштування**: URL і CSS-селектори сайту, headless, ліміти, Telegram.

## Автооформлення замовлення

«Налаштування» → «Автооформлення замовлення». Працює для завдань «Моніторинг + кошик»:
після додавання в кошик програма проходить чекаут (Нова Пошта, оплата при отриманні або посилання на оплату).

Запобіжники:
- **Пробний режим увімкнено за замовчуванням**: усе заповнюється, але «Підтвердити» не натискається.
  Вимкнення — лише з заданим лімітом і з підтвердженням у діалозі.
- **Ліміт суми**: без ліміту справжнє замовлення заборонене. Ціну з картки перевіряємо ще до кошика,
  а суму в чекауті (з усім, що лежить у кошику акаунта) — перед підтвердженням; нечитабельна сума = відмова.
- **1 замовлення на завдання**: перед кліком у БД (`checkouts`) атомарно резервується місце. Успішне замовлення
  або невідомий результат (збій/«Стоп» після кліку) блокують повтор назавжди — перевірте кабінет магазину.
- **Повторні кліки**: кнопку натискаємо рівно раз; перед цим на сторінку ставиться захист, що ігнорує
  подальші кліки/submit/Enter і вимикає кнопку.

## Telegram-сповіщення

1. Створіть бота в @BotFather → отримаєте токен. Напишіть своєму боту `/start`.
2. Chat ID дізнайтесь у @userinfobot.
3. «Налаштування» → «Telegram-сповіщення»: увімкнути, chat ID, токен (іде в Keychain) →
   «Надіслати тестове» → «Зберегти».

Приходять: товар з'явився в наявності / доданий у кошик (з кнопкою «Відкрити товар»),
зміна статусу замовлення і нова ТТН (з кнопкою відстеження на Новій Пошті).
Перший збір замовлень сповіщень не шле — лише подальші зміни.
Якщо в повідомлення передано посилання на оплату, з'являється кнопка «💳 Оплатити замовлення»:
вона лише відкриває сторінку оплати магазину, оплачуєте ви самі.

У devsite змінити статус замовлення для перевірки:
`http://127.0.0.1:8765/admin/order/100301?status=Відправлено&ttn=20450000000099`

## Під справжній сайт

Змінити в «Налаштуваннях» URL входу/кабінету/кошика і селектори (поле email, пароль,
кнопка входу, ознака входу, ознака наявності, кнопка «в кошик», товар у кошику).
Код чіпати не треба. Перевірка: одне завдання з інтервалом 30+ с і подивитись «Логи».

## Де що лежить

| Шлях | Що |
|---|---|
| `data/orderdesk.db` | SQLite: акаунти, проксі, завдання, кошик, логи, статистика |
| `data/sessions/` | `storage_state` акаунтів (cookies + localStorage), права 600 |
| `data/site.json` | налаштування сайту |
| Keychain «OrderDesk» | паролі акаунтів і проксі, токен Telegram |

`data/` у `.gitignore`: сесії = доступ до акаунтів, нікому не пересилати.
